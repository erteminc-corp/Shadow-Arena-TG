# SHADOW ARENA: ASHFALL — 1.0

Готовий до розміщення статичний проєкт: Canvas 2D, HTML, CSS, JavaScript. Компіляція, npm, Python і постійний ігровий сервер НЕ потрібні. Весь бій працює на пристрої. Оплати — окремий необов’язковий Cloudflare Worker із D1.

## Що всередині

- index.html — запуск гри.
- game.js — бій, хвилі, штучний інтелект, cut-out анімація, інтерфейс, збереження.
- style.css — адаптивний інтерфейс.
- locales.js — усі чотири мови: en, uk, ru, es-419.
- config.js — тільки публічна адреса платіжного Worker; початково порожня.
- arena.webp, warden.png, gloom.png, husk.png, archer.png, herald.png — оригінальні згенеровані ресурси.
- Вісім WAV — оригінальні синтезовані короткі ефекти.
- worker.mjs — серверні платежі через офіційний Bot API.
- deploy.html — копіювання Worker-коду й створення config.js у Safari.
- QA.md — звіт перевірок та обмеження.
- worker.test.mjs — необов’язкові тести для розробника; для публікації не потрібні.
- ART.md — походження графіки та спосіб анімації.

Усі файли навмисно лежать в ОДНІЙ папці: Safari на iPhone простіше завантажувати окремі файли, ніж дерево вкладених каталогів. Не публікуй лише ZIP: GitHub Pages сам архіви не розпаковує.

## Геймплей

WASD / стрілки — рух; Space — ривок; Escape — пауза. Миша керує меню. На сенсорному екрані — лівий джойстик і правий ривок із мультитачем. Атака автоматична. Ривок дає коротку невразливість, базове відновлення — 4 с. Рекорди та налаштування зберігаються тільки на поточному пристрої й origin браузера. Синхронізації немає.

Бос кожної п’ятої хвилі. Попередження: сектор — удар, довга смуга — ривок або постріл, коло зі спицями — радіальний залп. Після хвилі обери одну із трьох карток. Жодної реклами, платних бонусів або обмежень без оплати.

## Частина A. GitHub Pages лише з iPhone

1. У ChatGPT відкрий SHADOW-ARENA-ASHFALL.zip. Через «Поділитися» → «Зберегти у Файли» збережи архів у Downloads або iCloud Drive. Дочекайся завершення завантаження.
2. У застосунку «Файли» торкнися ZIP один раз: iOS розпакує його. Відкрий створену папку; всередині мають бути index.html, game.js, зображення та інші файли.
3. У Safari відкрий https://github.com, увійди або створи акаунт та підтвердь пошту. У меню профілю / «+» обери New repository. Назва: shadow-arena-ashfall. Видимість Public — підходить для Pages на безкоштовному особистому акаунті. Увімкни Add a README, натисни Create repository.
4. На вкладці Code натисни Add file → Upload files → choose your files. У системному виборі файлів відкрий розпаковану папку й обери файли. Якщо доступний множинний вибір, познач усі; якщо ні — повторюй завантаження частинами. Усі мають опинитися в корені репозиторію, поруч із README.md. Завантаження README з архіву може замінити початковий README — це очікувано.
5. Якщо Add file не видно: меню Safari біля адреси → «Запитати настільний вебсайт»; поверни iPhone горизонтально й зменш масштаб. Якщо Upload files прихований у меню «…», відкрий його. Завантажувати папку перетягуванням з iPhone не потрібно.
6. Напиши повідомлення коміту, наприклад Add ASHFALL, і підтвердь Commit changes у main. Якщо GitHub пропонує окрему гілку — створи pull request і Merge pull request через Safari. Для нового власного репозиторію зазвичай доступний прямий коміт.
7. GitHub дозволяє до 100 файлів за один браузерний upload, до 25 MiB на файл. Цей проєкт менший за обидві межі.
8. Settings репозиторію → Pages → Build and deployment → Source: Deploy from a branch → Branch: main → /(root) → Save.
9. Дочекайся успішної публікації. Перевір вкладку Actions або онови Settings → Pages. Адреса зазвичай https://ТВІЙ-ЛОГІН.github.io/shadow-arena-ashfall/ . Використовуй саме адресу, яку показує GitHub, з правильним регістром назви.
10. Відкрий адресу в Safari. Має з’явитися меню, зображення героя, вибір зброї, арена. Перевір обидві зброї, ривок і паузу. Якщо бачиш 404, перевір розташування index.html у корені, main і завершення деплою.
11. Якщо відображається старий код після оновлення, закрий вкладку та відкрий URL із ?v=2. У Telegram повністю закрий Mini App і відкрий знову. Проєкт не встановлює service worker, тому прихованого офлайн-кешу гри немає.

Відкриття index.html через Quick Look у «Файлах» не є браузерним запуском гри. Тестуй через HTTPS. Інтернет потрібен для першого завантаження ресурсів; надійний повний офлайн-режим тут не заявлений.

## Частина B. Telegram

1. У Telegram відкрий офіційного @BotFather. Надішли /newbot.
2. Введи назву, наприклад SHADOW ARENA: ASHFALL, потім унікальний username із закінченням bot, наприклад MyAshfallArenaBot. Показувану назву згодом можна змінити через /setname.
3. BotFather видасть токен. НЕ вставляй його в GitHub, config.js, HTML, повідомлення підтримки, URL Safari або скриншоти. Він потрібен тільки в Cloudflare Secrets для необов’язкових платежів.
4. Надішли /setmenubutton, обери бота. Введи HTTPS-адресу GitHub Pages. Коли BotFather попросить напис кнопки, введи PLAY. Послідовність запитів BotFather може змінюватися — відповідай відповідно до його поточного повідомлення.
5. Відкрий чат зі своїм ботом → Start. Кнопка меню PLAY запускає гру. Для роботи самої Mini App відповідь на /start від backend не потрібна. Після налаштування Worker бот також відповідатиме на /start.
6. Необов’язково: /mybots → твій бот → Bot Settings → Configure Mini App / Main Mini App. Увімкни Main Mini App та встанови ту саму HTTPS-адресу. Це дає кнопку запуску в профілі й можливість посилання https://t.me/USERNAME?startapp. Назви пунктів можуть відрізнятися між версіями BotFather.
7. Перевір саме Mini App, а не лише сторінку у вбудованому браузері. Для оплати потрібні справжні підписані initData від запуску через кнопку бота.
8. Дай посилання знайомим із Android, iOS, планшетом і Desktop. Перевір запуск, рух, дві одночасні дії пальцями, згортання, паузу, поворот екрана. На телефоні рекомендована вертикальна орієнтація; примусове системне блокування орієнтації не використовується.

## Частина C. Необов’язкові Telegram Stars

Без цієї частини гра вже повністю запускається. Кнопка підтримки чесно повідомляє про недоступність платежів. Платежі не активуються автоматично після розпакування ZIP.

### C1. Cloudflare Worker у Safari

1. Створи акаунт на https://dash.cloudflare.com. Відкрий Workers & Pages у розділі Compute / Compute & AI. Обери Create application → Create Worker / Start with Hello World, задай назву ashfall-stars і Deploy. Потрібен саме Worker із кодом, не статичний Pages-проєкт.
2. У новій вкладці Safari відкрий адресу своєї гри, додавши deploy.html: https://ТВІЙ-ЛОГІН.github.io/shadow-arena-ashfall/deploy.html.
3. Натисни «Скопіювати Worker». Якщо буфер обміну заборонений, виділи весь текст у полі коду та скопіюй вручну. Це тільки публічний код без секретів.
4. Повернися до Worker → Edit code. Обери основний JavaScript-файл редактора, заміни весь Hello World скопійованим worker.mjs. Натисни Deploy. Розширення основного файлу в редакторі може бути .js — код ES module export default сумісний.
5. Мобільний редактор Cloudflare не гарантує зручність на кожній версії Safari. Реальний обхід: «Запитати настільний вебсайт», горизонтальний екран, зменшення масштабу; у редакторі довге натискання → Select All → Paste. Копіювання роби через deploy.html, без локального редактора. Якщо саме твоя версія Safari взагалі не дозволяє вставити код у редактор, універсального гарантованого обходу тільки цими трьома застосунками немає. Гру все одно можна опублікувати без Stars; не потрібно вставляти токен у клієнт заради обходу.

### C2. D1 та конфігурація

D1 потрібна тільки для обліку пожертв, захисту від повторів і повернень. Вона не зберігає забіги, рекорди, імена або листування.

1. У Cloudflare відкрий Storage & databases → D1 → Create database. Назва ashfall-payments. Створи базу.
2. Worker → Bindings → Add binding → D1 database. Variable name: DB. Обери ashfall-payments → Add binding. Якщо Cloudflare попросить Deploy — підтвердь.
3. Worker → Settings → Variables and Secrets → Add. Додай три значення з типом Secret:
   - BOT_TOKEN — токен саме того бота, через якого відкривається гра.
   - WEBHOOK_SECRET — випадковий секрет щонайменше 32 символи; тільки A–Z, a–z, 0–9, _ та -. Це окреме значення, не токен бота.
   - ADMIN_SECRET — інший довгий випадковий секрет для твоєї сторінки налаштування. Не використовуй той самий секрет двічі.
4. Додай звичайні текстові Variables:
   - GAME_ORIGIN: https://ТВІЙ-ЛОГІН.github.io — без шляху репозиторію та без фінального /.
   - GAME_URL: повна HTTPS-адреса гри з назвою репозиторію та /.
   - PAY_SUPPORT: твій реальний контакт, наприклад @твій_username. Переконайся, що він приймає повідомлення.
   - TELEGRAM_TEST: false для звичайного Telegram; true тільки для окремого тестового бота.
5. Збережи/Deploy. Secrets не повинні з’явитися в коді. Збережи ADMIN_SECRET приватно — він потрібен наступного кроку. Не зберігай секрети в репозиторії навіть якщо він приватний.

### C3. Webhook без токена в адресному рядку

1. Скопіюй адресу Worker з Cloudflare, наприклад https://ashfall-stars.username.workers.dev.
2. Відкрий її з /admin у Safari. Це вбудована сторінка керування. Вона не просить BOT_TOKEN.
3. Введи ADMIN_SECRET у парольне поле. Натисни Initialize database + register webhook.
4. Worker сам створить таблиці D1, викличе setWebhook із secret_token, налаштує /start, /support, /terms, /paysupport та кнопку PLAY. Токен буде використаний лише всередині Worker.
5. Очікуй {"ok":true,...}. Кнопка Webhook status + Stars balance показує стан webhook і баланс. Якщо помилка — перевір binding DB та всі значення з C2. Нікому не передавай результат, якщо там є приватні дані.
6. На deploy.html встав тільки базову адресу Worker та натисни «Завантажити config.js». Збережи файл у «Файли».
7. Якщо iOS додала суфікс до імені, перейменуй файл точно на config.js. У GitHub Upload files заміни існуючий config.js. Commit changes. Дочекайся Pages deployment.
8. Закрий і заново відкрий Mini App. У меню підтримки прочитай умови, увімкни згоду й обери 10 / 25 / 50 / 100 Stars. На звичайній вкладці Safari оплата недоступна: немає підписаних Telegram initData.

### C4. Офіційне тестове середовище без реальних витрат

Це окремий Telegram, а не перемикач «тест» у звичайному боті. Не використовуй Stripe TEST MODE: тут цифрові платежі XTR.

1. За офіційною документацією Telegram для iOS: торкнися значка Settings 10 разів → Accounts → Login to another account → Test. Зареєструй/увійди в окремий тестовий акаунт. Доступність debug-меню залежить від клієнта; якщо пункту немає, тестове середовище на цій інсталяції не перевірене, реальні платежі не є його еквівалентом.
2. У тестовому Telegram створи ОКРЕМОГО бота через тестового @BotFather. Тестові користувачі й боти ізольовані від основної мережі.
3. Зроби окрему копію GitHub-репозиторію/Pages для тесту, окремий Worker і окрему D1. Не перемикай робочий продакшн на тест посеред платежів.
4. У тестовому Worker встанови токен тестового бота, TELEGRAM_TEST=true, GAME_URL тестової гри, її GAME_ORIGIN; інші secrets теж окремі. Код сам використовує Bot API шлях /bot<TOKEN>/test/METHOD. Ти не вводиш цей шлях із токеном у Safari.
5. Виконай /admin → Initialize database + register webhook. Підключи тестовий Worker у config.js тестової гри. Запускай гру кнопкою тестового бота всередині тестового Telegram.
6. Обери 10 Stars і заверши тестову оплату в офіційному інтерфейсі тестового клієнта. Якщо тестовий баланс/покупка Stars пропонується клієнтом, використовуй тільки тестову мережу. Не вводь банківські реквізити для цього тесту.
7. Перевір: відкриття invoice; скасування; успішну оплату; повторне відкриття; подяку лише після successful_payment; /paysupport. На /admin перевір getWebhookInfo: немає актуальної помилки доставки. У D1 таблиця payments повинна мати один запис на оплату, навіть при повторі webhook.
8. Тут реальний тест не виконувався: потрібні твій тестовий акаунт і бот. Якщо тестовий клієнт не дозволяє завершити рахунок, не вважай це перевіреним платежем.

### C5. Справжні платежі та підтримка

1. Після тестування створи/використай окремий production Worker із production BOT_TOKEN, production D1, TELEGRAM_TEST=false та production GAME_URL. Повтори /admin setup. У бойовому config.js має бути його адреса.
2. Перевір невелику пожертву 10 Stars у звичайному Telegram. Це вже СПРАВЖНЯ витрата 10 Stars, не безкоштовний тест. Жодних ігрових бонусів не буде.
3. Подяка з’явиться лише коли Worker одержав successful_payment і записав його в D1. Статус paid, який повернув клієнтський openInvoice, сам по собі не вважається доказом.
4. Якщо підтвердження затримується, гра дозволяє продовжити. Подивися receipt у Telegram та записи D1; не здійснюй нову оплату лише через затримку подяки. Автоматичне опитування клієнта обмежене 10 спробами.
5. Перевір надходження на /admin → Webhook status + Stars balance. Worker викликає getMyStarBalance. Також перевір Stars balance свого бота у доступних інструментах BotFather. Баланс і фактична можливість виведення — різні речі; виведення ця гра не реалізує.
6. /paysupport та /support повідомляють твій PAY_SUPPORT. Це реальний канал зв’язку, але відповіді на звернення надаєш ти, а не автоматичний бот.
7. Для повернення знайди конкретний платіж у D1 → payments: uid і charge. У /admin введи ці значення, натисни Refund this payment і підтвердь. Worker перевіряє, що ідентифікатори належать записаному платежу, й викликає refundStarPayment. Не публікуй таблицю платежів.
8. Якщо токен потрапив у публічний репозиторій, негайно відклич його через BotFather, видай новий, заміни Secret і повтори setup. Видалення рядка з файлу не прибирає токен з Git-історії.

Захист: HMAC initData та строк дії 1 година; Origin/CORS; whitelist сум; окремий webhook secret; атомарне резервування checkout; унікальні invoice і charge у D1; rate limit на підписаного користувача; приватний admin; жодних секретів у грі. Це не незалежний аудит безпеки та не захист від будь-якої DDoS-атаки. Безкоштовні квоти Cloudflare й GitHub мають обмеження; «безкоштовно» не означає необмежений трафік.

## Частина D. Оновлення

1. Збережи нові файли у «Файли» та розпакуй архів.
2. У тому самому GitHub-репозиторії Add file → Upload files завантаж нові файли з тими самими назвами. Збережи свій production config.js: не замінюй його порожньою конфігурацією з нового архіву.
3. Commit changes → дочекайся успішного Pages deployment. URL не зміниться, тому BotFather переналаштовувати не потрібно.
4. Перезапусти Mini App. Перевір зброю, налаштування, мову та рекорди. Версія localStorage лишається ashfall-v1; звичайне оновлення не стирає дані. Зміна домену або видалення браузерних даних — може.
5. Worker оновлюй окремо через Edit code → Deploy. Secrets і D1 залишай прив’язаними. Якщо нова версія змінює схему платежів, спершу перевір міграцію в окремому тестовому середовищі; поточний setup створює таблиці, але не є універсальним мігратором.
